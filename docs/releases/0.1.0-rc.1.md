# mdrefine 0.1.0-rc.1

First release candidate of Markdown Tools. npm package: `mdrefine`; executable:
`mdtools`. Requires Node.js 22.12 or newer. Upgrade with:

```sh
npm install --save-dev --save-exact mdrefine@0.1.0-rc.1
```

Release candidates publish to npm's `rc` channel, and `latest` follows them
until the first stable release.

## Fewer refused documents

The formatter's safety check refuses a whole document, and withholds a whole
`--write` batch, when a rule proposes an edit that would change the parsed
meaning. Five built-in rules proposed such edits for ordinary input; each now
produces a safe edit or leaves the construct alone:

- `style/wrap` keeps fence openers, math and Obsidian comment markers, HTML
  block starts, footnote definitions, `--` and `=` runs, and words ending in an
  unescaped backslash attached to a neighbour instead of moving them to a line
  boundary ([PR #68](https://github.com/viell-dev/slop-markdown-tools/pull/68),
  resolving [#46](https://github.com/viell-dev/slop-markdown-tools/issues/46)).
- `style/wrap` starts a task item's reflow after the checkbox and its separator,
  so `[x]` and the following spacing survive
  ([PR #64](https://github.com/viell-dev/slop-markdown-tools/pull/64), resolving
  [#47](https://github.com/viell-dev/slop-markdown-tools/issues/47)).
- `style/table` keeps each row's own cell count instead of padding short rows
  with new cells
  ([PR #61](https://github.com/viell-dev/slop-markdown-tools/pull/61), resolving
  [#48](https://github.com/viell-dev/slop-markdown-tools/issues/48)).
- `style/emphasis` and `style/strong` leave a node alone when the new marker
  would touch an existing delimiter, such as `_*foo*_` or `*foo*_bar`
  ([PR #67](https://github.com/viell-dev/slop-markdown-tools/pull/67), resolving
  [#49](https://github.com/viell-dev/slop-markdown-tools/issues/49)).
- `style/heading` escapes a trailing `#` run when converting a Setext heading,
  so `Sharp #` becomes `## Sharp \#` rather than losing the `#`
  ([PR #66](https://github.com/viell-dev/slop-markdown-tools/pull/66), resolving
  [#50](https://github.com/viell-dev/slop-markdown-tools/issues/50)).

## Obsidian link resolution

Note names, folder paths, and heading subpaths now match case-insensitively in
the Obsidian dialect, as Obsidian does, so `[[note]]` and `[[Note#heading two]]`
resolve to `Note.md` and `## Heading Two`. Notes whose paths differ only by case
are reported as ambiguous. Block identifiers still match exactly, and CommonMark
and GitHub resolution stays case-sensitive
([PR #69](https://github.com/viell-dev/slop-markdown-tools/pull/69), resolving
[#51](https://github.com/viell-dev/slop-markdown-tools/issues/51)).

## Line endings

Documents that use bare carriage returns are reflowed with carriage returns and
no longer end up with three line-ending styles. The line ending for new breaks
is taken from the document's first line break; previously a `\r\n` anywhere in
the document selected `\r\n`
([PR #65](https://github.com/viell-dev/slop-markdown-tools/pull/65), resolving
[#52](https://github.com/viell-dev/slop-markdown-tools/issues/52)).

## Performance

Measured on synthetic corpora with the scripts in `scripts/`:

- Applying many edits and locating many diagnostics were quadratic in the number
  of edits or findings; both are now linear
  ([PR #58](https://github.com/viell-dev/slop-markdown-tools/pull/58) and
  [PR #59](https://github.com/viell-dev/slop-markdown-tools/pull/59), resolving
  [#53](https://github.com/viell-dev/slop-markdown-tools/issues/53) and
  [#54](https://github.com/viell-dev/slop-markdown-tools/issues/54)).
- `style/wrap` and `style/table` detect the line ending once per document
  instead of once per paragraph
  ([PR #60](https://github.com/viell-dev/slop-markdown-tools/pull/60), resolving
  [#55](https://github.com/viell-dev/slop-markdown-tools/issues/55)).
- Formatting computes the original fingerprint only when an edit produces a
  candidate, reuses the final pass's findings instead of a fourth rule sweep,
  skips directive scanning when no directive text is present, and traverses
  trees with a plain walk. On a 2,000-note vault, `lint` is about a third
  faster, formatting changed notes about 40% faster, and re-formatting already
  formatted notes about half the time
  ([PR #70](https://github.com/viell-dev/slop-markdown-tools/pull/70), resolving
  [#56](https://github.com/viell-dev/slop-markdown-tools/issues/56)).

## Compatibility and verification

No public API, configuration-schema, or Node.js minimum changes. Existing beta.4
configurations remain valid. `unist-util-visit` is no longer a direct dependency
of the package. Behaviour differences to expect: nested emphasis such as
`*__foo__*` is now left as written rather than rewritten to `___foo___`;
documents mixing line endings follow their first line break; Obsidian vaults
containing notes that differ only by case receive new ambiguity diagnostics.

Regression coverage now includes direct tests for `style/heading`, wikilink
rewriting, dialect marker edge cases, end-of-document directives and comments,
CLI error paths, and a property test that mixes block-like atoms with list,
task, and quote prefixes
([PR #63](https://github.com/viell-dev/slop-markdown-tools/pull/63), resolving
[#57](https://github.com/viell-dev/slop-markdown-tools/issues/57)). The API and
configuration remain provisional until the first stable release.
