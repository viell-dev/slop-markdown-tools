# What's new in 0.6

mdrefine 0.6 covers what markdownlint and Prettier check in Markdown, reads
their settings when a project has no mdrefine configuration, and makes bare
`format` a check. This page shows the changes with examples; the
[changelog](../changelog.md) lists every change, and
[upgrading](../upgrading.md#060) says what to do when you update from 0.5.

## Highlights

- The [comparison with Prettier and
  markdownlint](../integrations.md#coming-from-prettier-or-markdownlint) lists
  every markdownlint rule and every Prettier Markdown option with the mdrefine
  rule that covers it.
- A project with only a markdownlint or Prettier configuration gets those
  settings, and `mdrefine config convert --write` turns them into an mdrefine
  configuration.
- 24 new rules, two of them in `recommended`, and new options for fourteen
  existing rules.
- `format` without `--write`, `--check`, or `--diff` fails when a file would
  change.

## Your markdownlint or Prettier settings

Without an mdrefine configuration, `lint` and `format` read a markdownlint or
Prettier configuration in the workspace, convert it, and say so on stderr. With
a `.markdownlint.jsonc` that asks for `*` bullets:

```jsonc
{
  "MD004": { "style": "asterisk" },
  "MD013": false,
}
```

`lint` reports a `-` bullet at markdownlint's severity, `error`:

```text
mdrefine: no mdrefine configuration; using markdownlint settings from .markdownlint.jsonc (2 conversion note(s): mdrefine config explain <file>; opt out: --no-competitor-config)
notes.md:3:1: error style/list-marker: Use "*" as the bullet list marker.
1 file(s) linted; 1 error(s), 0 warning(s).
```

`npx mdrefine config convert` prints the converted configuration and notes on
what it could not convert; `--write` saves it as `mdrefine.config.jsonc`.
`--no-competitor-config` turns the fallback off. While it applies,
markdownlint's inline configuration comments, Prettier's ignore comments, and
Prettier's `requirePragma` apply too. The
[fallback](../configuration.md#fallback-to-markdownlint-and-prettier) lists the
files it reads and leaves out.

## `format` checks by default

Bare `format` prints the diff and exits `1` when a file would change, so it can
run in CI as it is. `format --diff` prints the same diff and exits `0`,
`format --check` names the files, and `format --write` writes them; see [exit
codes](../cli.md#exit-codes).

## Block quotes in `recommended`

[`style/quote-marker`](../rules/style/quote-marker.md) writes one space after
each `>`, and [`style/lazy-continuation`](../rules/style/lazy-continuation.md)
writes the `>` or the indentation on lines that continue a quote's or a list
item's paragraph without it. Before:

```markdown
>A quote whose text fills the line and goes on long enough to need a second line
when it is wrapped.
```

After:

```markdown
> A quote whose text fills the line and goes on long enough to need a second
> line when it is wrapped.
```

## More formatting in `recommended`

- [`style/table`](../rules/style/table.md) formats tables inside lists and block
  quotes.
- [`style/heading`](../rules/style/heading.md) removes a heading's indentation
  and writes one space after its hashes: `  ##  Install` becomes `## Install`.
- [`style/block-spacing`](../rules/style/block-spacing.md) puts a blank line
  around fenced code blocks and tables, as it does around headings and lists.
- [`content/image-alt`](../rules/content/image-alt.md) also reports an HTML
  `<img>` without an `alt` attribute.

Before:

````markdown
Run it:
```sh
npm test
```
Then commit.
````

After:

````markdown
Run it:

```sh
npm test
```

Then commit.
````

## New rules in no preset

Enable these under `rules` in the configuration. Each rule's page has examples
and options.

Style rules, which `format` fixes:

- [`style/code-block`](../rules/style/code-block.md): code blocks in one form,
  fenced or indented.
- [`style/definition-spacing`](../rules/style/definition-spacing.md): one space
  after a link reference definition's colon.
- [`style/line-ending`](../rules/style/line-ending.md): one line ending.
- [`style/link-title`](../rules/style/link-title.md): one kind of delimiter for
  link titles.
- [`style/no-tabs`](../rules/style/no-tabs.md): spaces instead of tabs in prose.
- [`style/prose-space`](../rules/style/prose-space.md): single spaces between
  words.
- [`links/allowed-notation`](../rules/links/allowed-notation.md): only the link
  forms you allow.
- [`links/bare-url`](../rules/links/bare-url.md): autolinks for bare URLs.

Problem rules, which report only:

- [`content/emphasis-spacing`](../rules/content/emphasis-spacing.md),
  [`content/inline-code-spacing`](../rules/content/inline-code-spacing.md), and
  [`links/text-spacing`](../rules/links/text-spacing.md): spaces inside markers
  that change what renderers show.
- [`content/html-element`](../rules/content/html-element.md): HTML elements.
- [`content/line-length`](../rules/content/line-length.md): long lines in
  headings, code blocks, and tables.
- [`content/proper-names`](../rules/content/proper-names.md): misspelled
  capitalization of names.
- [`content/shell-prompt`](../rules/content/shell-prompt.md): `$` prompts in
  shell blocks without output.
- [`links/descriptive-text`](../rules/links/descriptive-text.md): links whose
  text is "here".
- [`links/reversed`](../rules/links/reversed.md): links written as
  `(text)[url]`.
- [`structure/emphasis-heading`](../rules/structure/emphasis-heading.md): bold
  paragraphs used as headings.
- [`structure/heading-punctuation`](../rules/structure/heading-punctuation.md):
  headings that end with punctuation.
- [`structure/heading-template`](../rules/structure/heading-template.md): a
  required sequence of headings.
- [`structure/split-quote`](../rules/structure/split-quote.md): quotes split by
  a blank line.
- [`structure/unspaced-heading`](../rules/structure/unspaced-heading.md):
  `#Heading` without a space.

## New options

- [`style/wrap`](../rules/style/wrap.md): `mode: "never"` joins each paragraph
  onto one line.
- [`style/table`](../rules/style/table.md): `pipeStyle`, `style: "tight"`,
  `alignedDelimiter`, and `padding: "alignment"`.
- [`style/block-spacing`](../rules/style/block-spacing.md): `linesAbove`,
  `linesBelow`, and `includeFrontMatter` for headings.
- [`style/heading`](../rules/style/heading.md): `closing: "add"`.
- [`style/emphasis`](../rules/style/emphasis.md) and
  [`style/strong`](../rules/style/strong.md): `marker: "consistent"`.
- [`style/trailing-space`](../rules/style/trailing-space.md),
  [`style/thematic-break`](../rules/style/thematic-break.md), and
  [`style/list-indent`](../rules/style/list-indent.md): the choices that
  markdownlint and Prettier offer.
- [`links/valid`](../rules/links/valid.md): `ignoredFragments` and `exactCase`.
- [`links/undefined-reference`](../rules/links/undefined-reference.md):
  `shortcutSyntax` and `ignoredLabels`.
- [`links/unused-definition`](../rules/links/unused-definition.md) and
  [`links/empty`](../rules/links/empty.md): `ignoredDefinitions`, so
  `recommended` no longer reports a comment written as `[//]: # (note)`.
- [`structure/heading-increment`](../rules/structure/heading-increment.md):
  `frontMatterTitle`.
- [Code formatters](../configuration.md#front-matter-formatters) can format YAML
  and TOML front matter with a tool you choose.
