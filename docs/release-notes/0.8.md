# What's new in 0.8

mdrefine 0.8 adds three opt-in workflows and improves formatting preservation:

- Audit Markdown source navigation from entry pages you choose.
- Put recognized sentences on separate lines, wrapping long sentences to width.
- Convert disallowed inline links and images to full references.
- Preserve Obsidian, Forgejo, and Gitea heading destinations during autolink
  fixes.
- Wrap VitePress whitespace entities without discarding other paragraph fixes.

Existing configurations keep their defaults. There are no required [upgrading
steps](../upgrading.md); install 0.8.3 to use these options.

## Documentation in 0.8.3

Shared command-line, API, link-rule and navigation-audit guidance introduces
optional application syntax where it matters. Obsidian note links, embeds and
notes-folder boundaries are explained without requiring prior knowledge of the
application. The workspace root and Obsidian's notes folder remain distinct.

The contributor guide in the installed package links specialist maintenance
procedures through their public repository pages. The shorter entry guide routes
contributors to focused dependency, testing and verification procedures.

## Fixes in 0.8.2

Suppression comments now take effect individually when they share an HTML block.
For example, the directive below protects the heading on the next line:

```markdown
<!-- ordinary comment --> <!-- mdrefine-disable-next-line style/emphasis -->
# *Keep these markers*
```

The same handling preserves directives in lists and quotes, including tab
indentation. Comments inside code examples and quoted HTML attributes do not
become directives; the [configuration
guide](../configuration.md#suppression-comments) explains their boundaries.

The navigation audit now follows literal brace filenames such as `{{guide}}.md`
and accepts braces in external URLs without treating them as unknown dynamic
navigation. Local files and supplied buffers named `__proto__` also remain
available as link targets.

Plugin loading follows Node.js's active module conditions when synchronous ESM
loading is disabled. Prettier fallback and conversion report the unknown
`extends` option without attempting to load its target or inherit its settings.

## Audit navigation from explicit entries

A repository can have valid individual links while a page remains unreachable
from its entry pages. The new audit follows modeled source links and reports
eligible Markdown documents it cannot reach:

```sh
npx mdrefine audit reachability --entry README.md --entry docs/index.md
```

The audit only reports. It never deletes or rewrites documents, and ordinary
linting and formatting do not run it. Unsupported navigation or unreadable
inputs make the audit incomplete: it explains the missing coverage, withholds
definitive unreachable findings and exits with code 2. Website sidebars and
generated navigation are outside its source graph. See the [audit
guide](../reachability.md) for scope, reports and the Node API.

## Wrap prose by sentence

Set `mode: "sentences"` on `style/wrap` to start each recognized sentence on its
own line while keeping long sentences within the configured width:

```jsonc
{
  "rules": {
    "style/wrap": ["warn", { "mode": "sentences", "width": 80 }],
  },
}
```

Before:

```markdown
First sentence. Second sentence uses **emphasis**. A third sentence follows.
```

After:

```markdown
First sentence.
Second sentence uses **emphasis**.
A third sentence follows.
```

Recognition uses English-oriented heuristics; it is not a language or grammar
checker. Existing hard breaks and protected syntax remain. The [rule
page](../rules/style/wrap.md) explains abbreviations, punctuation and renderer
limits. No preset enables sentence mode.

## Convert inline links to full references

Enable conversion explicitly on `links/allowed-notation`:

```jsonc
{
  "rules": {
    "links/allowed-notation": ["warn", { "inline": false, "fixTo": "full" }],
  },
}
```

Before:

```markdown
Read [the guide](https://example.com/setup "Setup").
```

After:

```markdown
Read [the guide][mdrefine-link-1].

[mdrefine-link-1]: https://example.com/setup "Setup"
```

Labels and alternative text retain their source. Safe matching definitions can
be reused; new labels avoid existing definitions and authored reference-like
text. Obsidian links only reuse eligible existing definitions, and its images
stay inline to preserve Live Preview. Source-sensitive headings and callout
titles retain their notation. See the [rule
page](../rules/links/allowed-notation.md) for the conversion boundaries.

## Preserve Obsidian heading destinations

Obsidian accepts both visible heading text and authored heading source as link
destinations. Converting this heading's link to an autolink could invalidate a
link from another note:

```markdown
# [https://example.com](https://example.com)
```

`links/allowed-notation` now reports such links without an autolink fix inside
Obsidian headings. Eligible body links still receive fixes. This requires no
configuration change.

## Preserve Forgejo and Gitea heading targets

Autolink fixes keep a heading's original link notation when rewriting it would
change its native fragment targets. Eligible body links in the same document
still format, and headings with an explicit stable ID remain eligible when that
target stays intact. This preserves links from other pages without requiring a
configuration change.

## Wrap VitePress whitespace entities

Wrapping paragraphs containing whitespace entities such as `&#32;` no longer
refuses harmless edits and discards other paragraph fixes in the same file.
Existing rendered spacing and Vue's newline-sensitive element gaps stay intact.

## Keep GitHub lazy HTML protection efficient

Documents with many alternating list and quote containers followed by lazy HTML
tag lines could make protection collection revisit the same blocks repeatedly.
The collector now locates each region's final block directly while retaining the
same protected ranges and formatting behavior.

## Keep Prettier pragma detection efficient

Prettier fallback with `requirePragma: true` now checks leading comments in
linear time, including incomplete comments. The same pragmas enable formatting;
files without one remain unchanged.

## Clearer diagnostics

When `style/inline-code` removes padding without reducing the backtick count,
its diagnostic now names padding removal. The rule's behavior is unchanged.

Conflicting `fixTo: "full"` and `full: false` options now produce a message that
names both settings. Running `mdrefine audit` without a subcommand names
`reachability` as the required command; `audit --help` still succeeds.
